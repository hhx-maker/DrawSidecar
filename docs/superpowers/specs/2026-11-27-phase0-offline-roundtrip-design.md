# DrawSidecar Phase 0 离线文件闭环设计

日期：2026-11-27

状态：已获用户确认，待实现计划

## 目标

交付一个最小可用的 React/Vite/PWA 闭环，支持用户主动导入 PNG、在 Canvas 中预览、按源图尺寸导出透明 PNG，并提供剪贴板增强入口和文件回退。应用安装并缓存完整后，核心操作不依赖网络、电脑或后端服务。

本阶段不实现线稿缺口检测、区域分析、填色、项目数据库或复杂视觉算法。相关能力留给后续 Phase 1/2。

## 交互布局

采用混合式入口。没有图像时显示导入起始卡，导入完成后进入连续工作台，不增加多步骤向导。

宽屏工作台固定为三列。

- 左侧工具区放置导入 PNG、粘贴图像、导出 PNG、复制图像和撤销。
- 中间区域显示透明棋盘格上的 Canvas 预览。
- 右侧仅显示低干扰状态，包括文件名、像素尺寸、Alpha 状态、离线状态和错误提示。

右侧不放高频操作，以减少误触。窄屏下左侧工具区收缩为底部工具条，右侧状态区折叠为可展开信息面板。关键触控目标保持适合触控的尺寸，不依赖 hover。

## 数据流与架构

应用由 Vite 构建的静态资源和 Service Worker 提供离线入口。用户选择 PNG 后，应用校验文件类型、文件大小和解码尺寸，保留原始 Blob，并创建一份用于预览的 ImageBitmap。Canvas 使用原始像素宽高作为坐标基准，CSS 尺寸变化只改变显示比例，不修改图像数据。

导出使用原始尺寸的离屏 Canvas 生成透明 PNG Blob，提供下载和复制图像两个入口。原始文件不可覆盖。导入/导出服务与 Canvas 坐标映射保持独立，便于后续接入 Worker 和项目持久化。

本阶段不引入后端、IndexedDB 项目数据库、OpenCV 或 Worker 图像算法。

## 错误与恢复

- 无图像时导出操作不可用。
- 文件类型、损坏内容、超限尺寸或超限文件大小显示明确中文错误。
- 导入失败时保留当前项目，不替换已有图像。
- 剪贴板先做能力检测。权限或格式失败时显示原因，并保留文件输入和下载路径。
- 离线状态只有在必需资源缓存完成且 Service Worker 已控制页面后才显示为离线就绪。

## 测试与验收

单元测试覆盖 PNG 头部尺寸读取、透明像素 Alpha、隐藏 RGB 不形成伪线条、原样导出宽高，以及四角定位标记和偏心标记的坐标保持。集成测试覆盖导入、预览、导出 Blob、无图像禁用导出、损坏文件提示和剪贴板能力缺失时的文件回退。

Playwright 使用生产构建，确认 Service Worker 激活后断网重新导航，验证新页面仍能启动并完成导入、预览和导出。响应式检查覆盖 320、400、768、1024 CSS px。

真实 iPadOS Safari、主屏幕 PWA 和 Procreate 的文件/剪贴板往返、图层缩放、居中、Alpha 和像素对齐记录在 `docs/ipad_test.md`。没有真机或实测证据时标记 `MANUAL_PENDING`。

## Phase 0 成功标准

- 生产构建可以在本地静态预览服务器上运行。
- 断网重新加载仍可打开应用并完成 PNG 导入、预览和导出。
- 导出 PNG 的宽高、Alpha 和像素坐标与源图一致。
- 原始 Blob 不被覆盖。
- 用户图像没有网络上传、遥测或第三方运行时请求。
- 未执行的 iPad/Procreate 项目明确记录为 `MANUAL_PENDING`。
