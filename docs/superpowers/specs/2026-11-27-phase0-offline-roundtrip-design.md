# DrawSidecar Phase 0 离线文件闭环设计

日期：2026-11-27

状态：用户已审查并批准，修订后进入实现计划

## 目标与范围

交付一个最小可用的 React/Vite/PWA 闭环，支持用户主动导入 PNG、在 Canvas 中预览、按源图尺寸导出透明 PNG，并提供剪贴板增强入口和文件回退。应用安装并缓存完整后，核心操作不依赖网络、电脑或后端服务。

Phase 0 不包含图像编辑，因此不实现 Undo/Redo。界面可以提供重置视图和清空当前图像。Phase 0 不引入 IndexedDB 项目数据库、OpenCV、Worker 图像算法、AI 模型、LLM、Agent 或后端，也不提供项目自动保存。用户关闭页面后可能需要重新导入图像。线稿缺口检测、区域分析、填色和其他视觉辅助留给后续阶段。

## 交互布局

采用混合式入口。没有图像时显示导入起始卡，导入完成后进入连续工作台，不增加多步骤向导。

宽屏工作台固定为三列。

- 左侧工具区放置导入 PNG、粘贴图像、导出 PNG、复制图像、重置视图和清空图像。
- 中间区域显示透明棋盘格上的 Canvas 预览。
- 右侧仅显示低干扰状态，包括文件名、像素尺寸、Alpha 状态、离线就绪状态和错误提示。

右侧不放高频操作，以减少误触。窄屏下左侧工具区收缩为底部工具条，右侧状态区折叠为可展开信息面板。关键触控目标保持适合触控的尺寸，不依赖 hover。

## 原始文件、预览和派生输出

原始 PNG Blob 在导入后保持不可变，作为文件导出的首选数据源。Canvas 仅用于预览，不负责未修改原始文件的重新编码。未修改的 PNG 导出直接复用原始 Blob，导出前后以 SHA-256 测试验证字节级一致性。

导入元数据至少保留源图像宽度、高度、Alpha 存在性、像素坐标体系和原始 PNG 元数据。浏览器解码得到的 `ImageBitmap` 或兼容回退对象只用于显示，不替代原始 Blob。后续派生图像、Mask 和透明图层可以通过独立的 Canvas 编码接口输出，本阶段不实现复杂图像处理。

文件导出和剪贴板导出分别验收。剪贴板不承诺保持字节级一致性，文件导出才承担原始 PNG 的字节保真要求。

## 数据流与架构

应用由 Vite 构建的静态资源和 Service Worker 提供离线入口。用户选择 PNG 后，应用先检查 PNG signature 和 IHDR 尺寸信息，再检查文件大小、总像素数和单边尺寸，随后解码并再次核验实际尺寸。应用保留原始 Blob，并创建用于预览的图像对象。Canvas 使用原始像素宽高作为坐标基准，CSS 尺寸变化只改变显示比例，不修改图像数据。

导出时，未修改图像直接返回原始 Blob。派生输出通过预留的透明图层编码接口生成 Blob。原始文件不可覆盖。导入/导出服务、图像元数据和 Canvas 坐标映射保持独立，便于后续接入 Worker 和项目持久化。

## 剪贴板与文件交换

Clipboard API 只能由用户主动操作触发。点击复制前不执行会丢失用户激活状态的耗时异步操作，优先使用已经准备好的 PNG Blob，必要时使用 `ClipboardItem` 的 Promise 值。实现不依赖统一的 `clipboard-read` 或 `clipboard-write` 权限查询。

运行时分别检测 Clipboard API、ClipboardItem、PNG MIME 类型和 Web Share API。剪贴板能力缺失、权限拒绝、格式不支持或写入失败时显示明确提示，但不得影响文件导入和文件导出。ImageBitmap 不可用或解码失败时提供兼容的 HTMLImageElement/Object URL 回退，并在不再使用时释放 ImageBitmap 与 Object URL。

## 离线就绪与部署

使用 `vite-plugin-pwa` / Workbox 或同等可靠的本地资源预缓存机制。所有必要的 HTML、JavaScript、CSS、图标和运行资源均来自本地构建产物，禁止运行时 CDN、外部字体、第三方资源和遥测。

界面区分网络状态和离线就绪状态。只有 Service Worker 已控制当前页面，且当前版本的必要资源已完整缓存后，才显示“离线就绪”。Service Worker 注册成功本身不能触发该状态。实现需要处理缓存缺失、缓存清理、版本更新和 Service Worker 尚未接管页面的情况，并保留当前可用页面。

验证 GitHub Pages 子路径部署下的 Vite `base`、manifest、`start_url`、`scope` 和 Service Worker 路径。用户图像不写入静态站点、网络请求、URL 查询参数、日志或遥测。

## 尺寸、内存与竞态

继承 AGENTS.md 的 Phase 0 限制。最大文件大小为 50 MiB，最大总像素数为 4096 × 4096，最大单边尺寸为 8192 px。解码前检查 PNG signature 和 IHDR 尺寸，避免异常声明造成大内存分配。解码后再次检查实际尺寸。超限图片明确拒绝，不静默缩放。

保留原始图像坐标体系。预览可以根据内存预算降采样显示，但不能影响源图和文件输出。及时释放 ImageBitmap、Object URL 和不再使用的 Canvas 缓冲区。连续快速导入必须通过序列号或 AbortController 忽略过期异步结果。大尺寸像素数组不放入频繁更新的 React 状态。

## 测试与验收

单元测试覆盖 PNG signature/IHDR 读取、文件大小和尺寸限制、非法 PNG、损坏 PNG、超大声明尺寸、半透明像素、完全透明但 RGB 非零的像素、隐藏 RGB 不形成伪线条、原始 Blob SHA-256 一致性和源图宽高/Alpha/坐标元数据。集成测试覆盖导入、预览、未修改文件导出、派生编码接口、无图像禁用导出、清空图像、损坏文件提示、剪贴板能力缺失与权限拒绝回退，以及连续导入异步竞态。

Playwright 使用生产构建，确认 Service Worker 控制页面且必要缓存完整后，断网进行全新页面启动、导入、预览和导出。测试缓存缺失时不得错误显示离线就绪，监控网络请求以验证无用户图像上传、第三方运行时请求和遥测。覆盖 Chromium 和 WebKit，以及 320、400、768、1024 CSS px 响应式布局。另行验证 GitHub Pages 子路径构建产物中的资源路径和 manifest。

真实 iPadOS Safari、主屏幕 PWA、飞行模式冷启动、Procreate 分屏、透明 PNG 对齐、剪贴板往返和 Web Share 行为记录在 `docs/ipad_test.md`。桌面 WebKit 通过不等于 iPad 真机通过。未实际执行的项目标记 `MANUAL_PENDING`。如果 Procreate 插入透明 PNG 时出现居中、裁切或位移，记录实际行为与复现步骤，不宣称图层对齐成功。

## Phase 0 成功标准

- 生产构建可以在本地静态预览服务器和 GitHub Pages 子路径配置下运行。
- Service Worker 控制页面且必要资源完整缓存后，断网新导航仍可打开应用。
- 断网状态下可以完成 PNG 导入、预览和导出。
- 未修改的 PNG 文件导出 SHA-256 与原始 Blob 一致。
- 导出 PNG 的宽高、Alpha 和像素坐标与源图一致，元数据按浏览器能力保留并记录限制。
- 原始 Blob 不被覆盖，用户图像没有网络上传、遥测或第三方运行时请求。
- 剪贴板失败不会阻断文件通道。
- 未执行的 iPad/Procreate 项目明确记录为 `MANUAL_PENDING`。
